#1. What Defines This Group

Identical node tree across all aspects (all 340 nodes and flatIndices match 1:1), but statesIndices.length differs across aspect variants.

Across all 2,858 packages in Slotomania, only ONE scene group falls into this category: sh-remote-BottomBarInSlotFaceliftV2 :: sceneFacelift@.object.

#Exact diff explained

In 16x9 and 19.5x9, one button had a mouse-hover substate (_hover_up, stateIdx: 37) configured inside its up state — turning one 2-child up state into a 3-child up state and adding +1 state, +4 hover actions, and +4 hover transitions. The underlying 340-node display tree is structurally identical across all 5 aspects.

#3. Potential Solution (Reduce to 1 Scene)

  1. Recommended (cleanest): Unify the button FSM across all 5 aspects by keeping the 429-state superset (including _hover_up on 4x3/3x2/5x3 is harmless on touch devices and consistent on desktop web), collapsing into 1 scene.object.tsx + 1 WbipSceneV3.
  2. Alternative (zero-risk automated path): Since all 340 flatIndices are identical, emit 1 scene.object.tsx and retain the two distinct FSM tables (3x2 for 4x3/3x2/5x3 and 16x9 for 16x9/19.5x9) in package.prefab.
