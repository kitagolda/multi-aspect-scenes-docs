#3. Potential Solution

#For 12a (Portrait-only, 7 groups)

6 of the 7 groups (scene*Portrait3x2.object vs scene*Portrait4x3.object) have zero differences (collapse like Group 01), and 1 (remote-MachineSidePanel.Tutorial :: sceneMaskTabSmallPortrait@.object) has only a top-level Position offset (collapse like Group 02). Note the naming convention: Portrait precedes the aspect token (sceneAdPOPortrait3x2.object).

#For 12b (Same-Tree Landscape + Portrait, 200 groups)

Collapse into 1 scene.object.tsx using orientation-aware byAspect(...) (keyed by tokens like "4x3" vs "4x3Portrait", or an isPortrait check) re-evaluated on viewPortChanged:

TSX 
// Collapsed single scene for game621.loading (covers both 4x3 and 4x3Portrait)
export const sceneName = "scene4x3.object";

export function build(contentManager: IContentManager, prefabData: IPrefabData): GameComponent {
    return (
        <RenderStatesNode>
            <SpriteNode
                SpriteName={byAspect({ "4x3Portrait": "vertical2.spr", default: "horizontal1.spr" })}
                Position={byAspect({ "4x3Portrait": { x: 119, y: -533 }, default: { x: -441, y: -219 } })}
                Scale={byAspect({ "4x3Portrait": { x: 1.1, y: 1.1 }, default: { x: 1.04, y: 1.04 } })}
            />
            <ContainerNode
                Position={byAspect({ "4x3Portrait": { x: 357, y: 737 }, default: { x: 357, y: 637 } })}
            >
                {/* ...loading progress bar... */}
            </ContainerNode>
        </RenderStatesNode>
    );
}

#For 12c (Structural Landscape + Portrait, 52 groups)

Keep separate Landscape and Portrait .tsx modules and wire them through the lazy @TsxScene proximity AR map — setTsxSceneAspectResolver already returns Portrait tokens first on portrait screens and Landscape tokens first on landscape screens, so only the active orientation chunk is downloaded:

TS 
@TsxScene("game614.loading/scene@.object", {
    "4x3": () => import("./tsx/scene4x3.object"),
    "4x3Portrait": () => import("./tsx/scene4x3Portrait.object"),
})

#Edge cases & gotchas

  • Orientation-switch behaviors: Preserve ChangeOrientationStateBehavior and TrackLandscapeBehavior interactions — when a mobile user rotates the device mid-session, either re-evaluate byAspect on viewPortChanged (12b) or let loadBoundTsxScenes lazily fetch the newly active orientation module (12c).
  • Asset preloading: When collapsing 12b into 1 .tsx with conditional SpriteName (horizontal1.spr vs vertical2.spr), verify that AssetPack / prefab manifests keep both orientation textures unless split into orientation bundles.
