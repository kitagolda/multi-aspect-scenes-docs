Group 01 — Identical Trees & FSM

Count
47 landscape groups (10.3% of 458)
Difficulty
Trivial (zero runtime logic required)
Target outcome
Collapse to 1 scene.object.tsx + 1 WbipSceneV3 entry in package.prefab.

#1. What Defines This Group

Every landscape aspect variant in the group (4x3, 3x2, 5x3, 16x9, 18x9, 19.5x9, etc.) has:

  • Identical node hierarchy (same node types, child counts, Ids, and flatIndices),
  • Identical property values on every single node (including root Position, Scale, and Bounds),
  • Identical FSM tables (same statesIndices, actionIndices, and transitionIndices lengths).

#Why does this happen in WBIP?

  1. The feature already uses runtime responsive layout inside the scene itself (for example SCREEN_ALIGNMENT_NODE, PROJECTION_BOUNDS_NODE, or code-behind positioning), so Flash simply exported identical copies for every target aspect ratio.
  2. Or the Flash build pipeline auto-generates aspect-suffixed exports (scene3x2.object, scene4x3.object, …) even when the designer never customized the per-aspect variants.

#2. Real WBIP Examples

#Example A: sh-remote-Ballinko.Arena — sceneArena@.object (6 identical aspects)

All 6 aspect variants (4x3, 3x2, 5x3, 16x9, 18x9, 19.5x9) are byte-for-byte structurally and property-wise identical:

  • Nodes: 92
  • FSM: 48 states, 1,045 actions, 142 transitions

#3. Potential Solution (Reduce to 1 Scene)

  1. In wbip-processor: Detect that all landscape variants in the @-group have identical trees and FSM tables. Emit only one canonical scene.object.tsx (e.g. from 3x2) exporting export const sceneName = "sceneArena3x2.object"; and keep only that one WbipSceneV3 entry in package.prefab.
  2. In @playtika/pixi + @TsxScene: Register the single canonical module for the @-pattern. When MultiPathSceneFactory probes sceneArena16x9.object or sceneArena4x3.object, TsxSceneRegistry resolves the single canonical module and SceneBuilder binds resource.data.scenesV3.get(tsxModule.sceneName).
TSX 
// Single canonical TSX file replaces all 6 aspect .tsx files:
export const sceneName = "sceneArena3x2.object";

export function build(contentManager: IContentManager, prefabData: IPrefabData): GameComponent {
    return (
        <ControlNode Id="arena">
            <RenderStatesNode>
                <ContainerNode Position={{ x: -213, y: 0 }}>
                    {/* ...identical tree across all 6 aspects... */}
                </ContainerNode>
            </RenderStatesNode>
        </ControlNode>
    );
}

#Edge cases & gotchas

  • Double-check FSM action values, not just counts: Before dropping duplicate WbipSceneV3 entries in wbip-processor, verify the actual actionIndices / statesIndices content matches (a handful of scenes can share identical counts while referencing different action indices — see Group 06).
  • Groups with a Portrait variant: 21 group(s) below also carry a *Portrait scene; check Group 12 for their orientation diff.
