Group 03 — Top-Level Uniform Scale + Centering Offset

Count
157 landscape groups (34.3% of 458) — the single largest category in the entire corpus
Difficulty
Easy
Target outcome
Collapse to 1 scene.object.tsx using a non-FSM responsive uniform-fit + centering wrapper.

#1. What Defines This Group

Every landscape variant has the exact same node tree and FSM. The only differences occur on the root node or a direct child (depth <= 1), exclusively on Position, Scale, and optionally Bounds.

  • 156 / 157 (99.4%) use uniform scaling (Scale.x === Scale.y, typically 0.80–0.90 on 4x3 and 0.95 on 3x2 / 16x9) paired with a centering (x, y) offset so the popup fits inside the narrower 4x3 viewport without clipping.
  • 1 / 157 uses non-uniform horizontal-only scaling (Scale.y = 1, Scale.x = 0.751 / 0.901) — sh-remote-PlayersProfile.Popup.Stash :: sceneTutorial@.object.

#Why does this happen in WBIP?

Popups are authored at a canonical design size (typically 3x2 960×640 or 16x9). When exporting for 4x3 (which is narrower relative to height), artists apply a uniform scale factor (e.g. 0.90) to the popup root or child[0] and shift (x, y) by (width * (1 - s) / 2, height * (1 - s) / 2) to keep it centered.

#3. Potential Solution (Reduce to 1 Scene)

Wrap the scene's content inside a non-FSM responsive fit wrapper (or apply an applyAspectFit helper on root / child[0] when that node has no FSM Position/Scale actions):

  1. Evaluate synchronously inside build() using Game.instance.screen.design.
  2. Re-evaluate on Game.instance.viewPortChanged (and detach listener on dispose()).
  3. Never mutate a node that is targeted by a WbipActionConnections Position or Scale tween — inspect WbipActionConnections during wbip-processor conversion and insert a non-FSM wrapper or apply the transform to the unaffected parent.
TSX 
// Collapsed single scene for LottoBonus.AreYouSurePopup
export const sceneName = "sceneAreYouSurePopup3x2.object";

export function build(contentManager: IContentManager, prefabData: IPrefabData): GameComponent {
    return (
        <ControlNode Bounds={{ x: 0, y: 0, width: 960, height: 640 }}>
            <AspectFitWrapper
                designWidth={960}
                designHeight={640}
                scales={{ "4x3": { scale: 0.9, x: 50, y: 33 }, default: { scale: 1, x: 0, y: 0 } }}
            >
                <RenderStatesNode>
                    {/* ...identical popup subtree... */}
                </RenderStatesNode>
            </AspectFitWrapper>
        </ControlNode>
    );
}
Important flatIndex rule: If AspectFitWrapper is added as an extra display node in the tree, it must not shift flatIndices for FSM binding (either apply fit directly to a non-animated existing node via ref/behavior, or exclude the synthetic wrapper from the flatIndex table).

#Edge cases & gotchas

  • Code-behind ScaleBehavior / view positioning: Some views in slotomania-ts already attach ScaleBehavior or read root.children[0].position. Check view bindings when migrating a feature so the TSX fit wrapper doesn't double-scale.
  • Full-bleed backdrop dimmer: If a popup's background fader lives inside the scaled child[0], uniform scaling to 0.90 can expose screen edges unless the fader is outside the fit wrapper or oversized (see Group 04 Aviator.WinPopup).
