Group 06 — Same Node Tree, FSM actionIndices Differ

Count
125 landscape groups (9.3% of 1,347)
Difficulty
Medium–Hard
Target outcome
1 scene.object.tsx (node tree & flatIndices are 100% identical!) paired with either FSM action deduplication / relative-offset conversion or compact per-AR FSM entries in package.prefab.

#1. What Defines This Group

Every landscape variant has:

  • Identical node hierarchy (same node types, child counts, Ids, and flatIndices),
  • Identical statesIndices.length (same state machine topology),
  • Different actionIndices.length (and/or transitionIndices.length) across aspects.

(Of the 125 groups, 7 have 0 static node-property diffs — only their FSM action tables differ!)

#Why does this happen in WBIP?

Flash exports absolute coordinates into keyframe animations (WbipActionResource with valueType: 3 = Point2D). When an animated widget is positioned at different (x, y) coordinates on 4x3 vs 3x2 vs 16x9:

  1. The exporter emits different startValue / endValue action resources per aspect.
  2. When a tween's start and end values happen to collapse or split across keyframes on one aspect (e.g. a hold segment splits into two segments or drops a redundant hold), actionIndices.length changes by a few entries (e.g. 282 vs 276 vs 281).

#3. Potential Solution (Reduce to 1 Scene)

Because the node tree and flatIndices are 100% identical, you ALWAYS get down to 1 scene.object.tsx immediately! For the FSM layer in package.prefab, there are three tiers of reduction:

  1. Tier 1 — Immediate 1-.tsx win (zero animation risk):
    • Emit 1 scene.object.tsx (with applyAspectOverrides for static node prop diffs).
    • Keep the lightweight per-AR WbipSceneV3 FSM tables in package.prefab (no node arrays needed — only the small FSM indices!), and let SceneBuilder bind the probed aspect's FSM onto the single shared TSX tree.
    • Why it works: flatIndices are identical across every aspect in this group, so every WbipActionBinding node index matches 1:1.
  2. Tier 2 — Dead-action & constant-hold deduplication in wbip-processor:
    • Prune unreferenced actions and merge adjacent identical-value hold actions. Many scenes with diffNodeCount === 0 collapse to a single shared WbipSceneV3 automatically after normalization.
  3. Tier 3 — Relative-offset tweens (full FSM collapse):
    • For scenes where every action diff is a constant translation delta (Δx, Δy) matching the target node's aspect offset, shift the offset onto a parent wrapper container (or convert the tween to relative deltas) so the animation keyframes become identical across all aspects and collapse into 1 WbipSceneV3.
TS 
// Tier 1 runtime binding in SceneBuilder:
// 1 shared TSX module builds the node tree (identical flatIndices for all ARs),
// while per-AR FSM table in package.prefab supplies aspect-baked tween coordinates:
const fsmSceneKey = resource.data.scenesV3.has(probedSceneName)
    ? probedSceneName
    : (tsxModule.sceneName ?? probedSceneName);

#Edge cases & gotchas

  • Do NOT blindly drop per-AR FSM entries if actionResources contain different startValue/endValue coordinates (as in sceneCoins@), or the animated element will visibly snap to the 3x2 coordinate the moment its state animation starts!
  • Wait for Tier 3 until verified: Only collapse the FSM itself once wbip-processor proves every action difference is either dead code or an exact constant offset captured by a wrapper node.
