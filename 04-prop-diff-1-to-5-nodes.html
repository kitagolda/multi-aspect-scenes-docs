Group 04 — Same Tree & FSM, 1–5 Nodes Differ

Count
278 landscape groups (20.6% of 1,347)
Difficulty
Medium
Target outcome
Collapse to 1 scene.object.tsx combining dynamic layout primitives (ScreenAlignmentNode, ProjectionBoundsNode, cover-scale) with a compact inline byAspect(...) prop map.

#1. What Defines This Group

Every landscape variant shares the exact same node tree and FSM (identical flatIndices, identical states/actions/transitions), and only 1 to 5 nodes deeper in the tree (depth >= 2, or non-Position/Scale/Bounds properties at top level) differ across aspects.

Common real-world patterns in this group:

  1. Popup fit + full-bleed BG dimmer counter-scale: Popup content scales to 0.90 on 4x3, while a child TILE_NODE / SPRITE_NODE dimmer counter-scales up (1.04 → 1.154) so it still fills the screen.
  2. Edge-pinned controls & HUD markers: Close buttons, corner badges, and onboarding callouts shift linearly along X as the viewport widens from 4x3 to 19.5x9.
  3. Spotlight masks & texture swaps: Onboarding scenes swap a mask texture (mask_panel.png vs mask_panel_4x3.png) and adjust MaskPosition / MaskOrigin / MaskScale.
  4. Hit areas & clipping rects: TouchArea and Scissor rectangles resize to match the aspect's panel Bounds.

#3. Potential Solution (Reduce to 1 Scene)

Because only 1–5 nodes differ and the tree + FSM are identical:

  1. Emit the shared JSX tree once with export const sceneName = "<baseScene>";.
  2. Replace formulaic diffs with dynamic primitives where obvious:
    • Full-bleed BG dimmers → ProjectionBoundsNode or screen-cover sizing (eliminating counter-scale math altogether).
    • Edge-pinned buttons/callouts → ScreenAlignmentNode or right/left edge offset from screen.design.width.
    • TouchArea synced to node Bounds.
  3. Use inline byAspect(...) for discrete overrides (mask texture swaps, spotlight coordinates, non-linear tweaks), evaluated at build() and updated on viewPortChanged:
TSX 
// Collapsed single scene for CoinsV2.Onboarding.InMachine (sceneMaskOnboardingPanel)
export const sceneName = "sceneMaskOnboardingPanel3x2.object";

export function build(contentManager: IContentManager, prefabData: IPrefabData): GameComponent {
    return (
        <RenderStatesNode>
            <MaskTextureNode
                TextureName={byAspect({ "4x3": "mask_panel_4x3.png", default: "mask_panel.png" })}
                MaskPosition={byAspect({
                    "4x3": { x: 113.2, y: 250 },
                    "16x9": { x: 143.2, y: 230.8 },
                    "19.5x9": { x: 148.2, y: 230.8 },
                    default: { x: 144.8, y: 230.8 },
                })}
                MaskOrigin={byAspect({
                    "4x3": { x: 109.2, y: 241.7 },
                    default: { x: 149.8, y: 230.5 },
                })}
                MaskScale={byAspect({ "4x3": { x: 1, y: 1.034 }, default: { x: 1, y: 1 } })}
            />
            <ControlNode
                Id="anim"
                Position={byAspect({
                    "4x3": { x: -50, y: -287 },
                    "5x3": { x: -66, y: -252 },
                    "16x9": { x: -73, y: -249 },
                    "19.5x9": { x: -56, y: -256 },
                    default: { x: -66, y: -251 },
                })}
                Scale={byAspect({ "4x3": { x: 0.75, y: 1.11 }, default: { x: 1, y: 1 } })}
            />
        </RenderStatesNode>
    );
}

#Edge cases & gotchas

  • Asset bundling (ALCK / AssetPack): When TextureName or SpriteName is conditional inside byAspect(...), ensure the prefab asset scanner still keeps all referenced textures/sprites in the bundle manifest (e.g. mask_panel_4x3.png AND mask_panel.png).
  • Live resize (viewPortChanged): If a property like TextureName or Scissor changes on resize, byAspect bindings need a lightweight re-apply hook rather than only running once during build().
