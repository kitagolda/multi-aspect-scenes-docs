Group 02 — Top-Level Offset / Bounds Only

Count
8 landscape groups (1.7% of 458)
Difficulty
Easy
Target outcome
Collapse to 1 scene.object.tsx with a small dynamic Position or Bounds adjustment on the root or a direct top-level child.

#1. What Defines This Group

Every landscape variant has the exact same node tree and FSM, with no Scale differences — only Position and/or Bounds differ on the root node or its direct children (depth <= 1).

Across the 8 real scenes in this group, three concrete sub-patterns appear:

  1. Root Bounds.height trim (2 groups): PlayersProfile.Popup.Inbox (sceneGroupItem@, socialStreakToggle@) only shrinks root#inbox.Bounds.height slightly on wider screens (132 → 128 → 123 → 117).
  2. Single HUD/popup child horizontal offset (4 groups): One direct child (coinsHolder, popup, gridHolderAdaptive) shifts horizontally between 4x3 and 3x2 (in HitGame.Popups.Complete, literally by 1 px: x=59 vs x=60!).
  3. Two top-level overlay children shift horizontally (2 groups): RoyalCommunalJackpot.Panel.Tutorial shifts turnRoyalText and maskSwitchPlace horizontally across 4x3, 3x2, 19.5x9; Login.DynamicSplash nudges progressStates and TxtContainer by ~11px on 4x3.

#3. Potential Solution (Reduce to 1 Scene)

Because neither Scale nor any deeper descendants differ, all 8 groups collapse cleanly into 1 scene.object.tsx using either:

  • Formulaic edge/center anchoring computed from Game.instance.screen.design (evaluated at build() and refreshed on Game.instance.viewPortChanged), or
  • A minimal inline byAspect(...) prop override when the designer picked discrete pixel values (like Inbox item heights 132 / 128 / 123 / 117 or the 1px nudge in HitGame.Popups.Complete).
TSX 
// Collapsed single scene for RoyalCommunalJackpot.Panel.Tutorial
export const sceneName = "sceneSwitchTutorial3x2.object";

export function build(contentManager: IContentManager, prefabData: IPrefabData): GameComponent {
    return (
        <RenderStatesNode>
            <ContainerNode
                Id="turnRoyalText"
                Position={byAspect({
                    "4x3": { x: 409, y: 160 },
                    "3x2": { x: 499, y: 169 },
                    "19.5x9": { x: 597, y: 169 },
                })}
            >
                {/* ... */}
            </ContainerNode>
            <ContainerNode
                Id="maskSwitchPlace"
                Position={byAspect({
                    "4x3": { x: 722, y: 0 },
                    "3x2": { x: 812, y: 9 },
                    "19.5x9": { x: 909, y: 9 },
                })}
            >
                {/* ... */}
            </ContainerNode>
        </RenderStatesNode>
    );
}

#Edge cases & gotchas

  • Verify the adjusted node is not targeted by a Position tween in WbipActionConnections (if it is, apply the offset on a non-FSM wrapper container around it instead of mutating the tweened node directly).
  • For HitGame.Popups.Complete (1px difference: x=59 vs x=60), you can simply collapse as identical without any runtime override.
